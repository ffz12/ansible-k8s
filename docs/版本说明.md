# 版本说明

本仓库的版本档案。每个版本记三样：**代码在哪个 commit**、**站点配置快照**、**已知状态与限制**。

## 为什么需要这份文档

代码可以靠 git tag 固化，但 **`inventory/hosts` 与 `inventory/group_vars/all/env.yaml` 是 gitignored 的**（`.gitignore:1` 与 `:17`）。同一个 tag 配不同的 `env.yaml` 能建出完全不同的集群（k8s 版本、CNI、网段、有无 lbvip 全在里面）。所以「生产跑的是 v1.0.0」这句话只说了一半 —— 站点配置必须在这里另记一份。

版本号用语义化版本 `vMAJOR.MINOR.PATCH`：

| 位 | 什么时候进 | 例子 |
|---|---|---|
| PATCH | 修 bug，行为不变 | 修一个渲染错误、补一句注释 |
| MINOR | 加能力，旧配置照旧能跑 | `kube_proxy_mode` 支持 nftables（默认不变） |
| MAJOR | 默认行为变了 / 有单向门 | calico 封装默认 `none` → `ipip`；`controlPlaneEndpoint` 改为无条件写 |

**打版本的时机是「交付/固化」，不是每个 commit。** 日常粒度 git 历史已经够了，版本号只标那些"某个站点从此跑这套"的节点。

### 已知状态与限制

以下三条是 `09cf972` **之后**才修的，生产的代码库里没有 —— 从这个 checkout 重跑相关 playbook 会退回旧行为：

**1. keepalived 仍是多播配置（最要紧）**

`55937c0 haproxy-ha/keepalived: VRRP 默认改单播 + 抢占策略可选 + 修 weight/auth_pass/state 三处失效配置` 不在本版本内。

即从此 checkout 重跑 `lb-haproxy-install.yaml`，渲出来是**多播 + `state MASTER` 写死 + `nopreempt` 实际失效 + `auth_pass` 被 8 字符截断**的那套 —— 也就是现网出现过永久双 MASTER（脑裂）的配置。

⚠ **生产机器上的 keepalived 配置可能已手工改成单播，与本 tag 的代码不一致。** 重跑 LB 相关 playbook 会把手工改动覆盖回多播。动 LB 之前先确认机器现状。

**但 `55937c0` 不是纯粹的修复 —— 它同时把 `weight` 改坏了。** 该 commit 把 `weight -30` 改成
`default(-5)`，而 keepalived 是把 weight 加到**本节点自己**的 priority 上、VRRP 再选**最高**者：
`-5` 时首台脚本失败只从 100 掉到 95，仍是最高 → **VIP 不动，健康检查等于装饰**。

所以这一条对本版本反而是**有利**的：`v1.0.0` 的 `weight` 还是 `-30`，在 2-3 台 LB 下选主正确，
**生产不受该回归影响**。`main` 侧已由 `1d9fea9` 改为按台数派生 `-(N × 10)` 修正。

**2. `k8s_compat` 缺 1.35 行 —— 本站点不受影响**（已核实）

`07c64c2 k8s_compat: 补 1.35 行` 不在本版本内，本版本的表只有 **1.28 / 1.34 / 1.36** 三行。

而本站点 `k8s_version: 1.36.3` → 表里有 `1.36` 行，`crictl_version` 取 `1.36.0`（crictl 上游确实只发 `x.y.0`），不会撞 404。**本条不适用。**

**3. calico 封装默认值不同 —— 本站点不受影响**（已核实）

`facdfb8 calico: 封装默认从 none 改为 ipip` 不在本版本内，本版本默认 `none`。

而本站点 `env.yaml` 显式写了 `calico_encapsulation: ipip`，以站点值为准。**本条不适用。**

**4. ⚠ calico manifest 结构与镜像版本可能不一致（需在集群上确认）**

这是填快照时新发现的，不在原先三条里。

本版本只有**一份** calico manifest 模板 `playbook/roles/cni/templates/calico.yaml.j2`，其头部注释写着「由 Calico 官方 **v3.31.3** manifest 对齐生成」，且 `defaults.yaml` 的 `calico_version` 兜底也是 `3.31.3`。

而本站点 `env.yaml` 写的是 `calico_version: 3.32.2`。这个变量只影响**镜像 tag**（`defaults.yaml:206-208` 的 `calico_images.*` 拼 `:v{{ calico_version }}`），不影响 manifest 的结构。所以按本版本部署会得到：

```
manifest 结构  = 官方 v3.31.3 的形状
镜像 tag       = v3.32.2
```

`main` 侧已把模板改成按版本存放（`f413eee` / `8384ffd`，3.31.3 与 3.32.2 共存），并加了「模板生成版本与 `calico_version` 不一致时部署即报错」的 guard（`ceafa50`）—— **那个 guard 不在本版本内**（已核 `git log v1.0.0 | grep ceafa50` 为空），所以本版本下这种不一致是**静默**的。

⚠ 但这不等于生产现在就是错的 —— `env.yaml` 可能是部署之后才改成 3.32.2 的。要确认实际跑的是什么：

```bash
kubectl -n kube-system get ds calico-node -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
kubectl -n kube-system get deploy calico-kube-controllers -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
```

出 `v3.31.3` = 部署时 `calico_version` 还是旧值，manifest 与镜像一致，没问题（只是 `env.yaml` 现在的值与实际不符）。
出 `v3.32.2` = 3.31.3 的 manifest 配 3.32.2 的镜像在跑。calico 小版本间通常兼容，但这是未经验证的组合，**重跑 `k8s-cni.yaml` 之前必须先弄清楚**。

**5. 两个已废弃变量仍留在 `env.yaml` 里**

`node_tuning_sysctl: true` / `node_tuning_keep_higher_net_buffers: false` —— 这两项在本版本里**零代码引用**（已核 `git grep -l node_tuning_sysctl v1.0.0 -- 'playbook/*'` 为空），`defaults.yaml:304` 那段注释也标了「已废弃(2026-09-09)」。那 13 项 sysctl 已合并进 `roles/init/files/sysctl.conf`。

留着无害但会误导 —— 读 `env.yaml` 的人会以为置 `true` 起了作用。改 sysctl 请直接改 `files/sysctl.conf`。
