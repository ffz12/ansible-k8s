# 部署说明 (ansible-k8s)

本文档覆盖从**主机清单**到**Kubernetes 集群**的完整部署流程（**在线 / 离线**均支持，离线整条链路传 `-e is_offline=true`），供团队维护参考。
底座（OS 初始化 → 容器运行时 → Harbor → 负载均衡）见 [一~十一]；**Kubernetes 部署层**（etcd → 控制面 → 多 CNI → worker）见 [十二~十五]。
（项目总览见 [README.md](../README.md)；手动安装 containerd 的原始笔记见 [containerd.md](containerd.md)。）

> **准备顺序**：① 写主机清单（[一](#一主机清单inventoryhostsini-格式)）→ ② 配核心变量（[二](#二配置核心变量group_varsallenvyaml)）→ ③ 配 SSH 免密（[三](#三ssh-免密)）→ ④ 底座 + Kubernetes（[快速上手](#快速上手命令清单)）

## 快速上手（命令清单）

> 在 **cpu01（控制机）** 上执行。这里是**唯一的完整命令清单**；主机清单/变量的详细示例见 [一](#一主机清单inventoryhostsini-格式)、[二](#二配置核心变量group_varsallenvyaml)，各步细节见对应章节。
> **在线 / 离线**：默认在线；离线整条链路加 `-e is_offline=true`（或在 inventory `[all:vars]` 里设一次，见 [十六](#十六离线部署完整流程)）。

```bash
cd ansible-k8s

# 0. 生成并填 inventory + 变量(详见 一 / 二)
bash init.sh                                     # 由 tmp/hosts.example 生成 inventory/hosts(已存在则跳过不覆盖)
vim inventory/hosts                              # 主机分组 + 连接信息, 见「一」
vim inventory/group_vars/all/env.yaml            # 域名/密码/版本/CNI/is_offline, 见「二」

# ---- 底座 ----
ansible-playbook playbook/add-control-key.yaml   # (可选)控制机→各节点免密(首次无免密时加 -k)
ansible-playbook playbook/init.yaml              # 系统初始化(离线在 env.yaml 置 is_offline=true)
ansible-playbook playbook/mount-nvme.yaml        # CPU 节点数据盘(单盘); GPU 多盘用 mount-nvme-lvm.yaml
ansible-playbook playbook/containerd-setup.yaml  # 装 containerd(★先挂盘再装)
ansible-playbook playbook/docker-install.yaml    # 装 docker(仅 Harbor 用, 复用已装的 containerd)
ansible-playbook playbook/harbor-install.yaml    # 装 Harbor(离线镜像中转站, 必须在 k8s 之前)
ansible-playbook playbook/harbor-trust.yaml      # 各节点信任 Harbor CA 证书
docker login harbor.local.clusters -uadmin -pHarbor12345   # 验证(在装了 docker 的节点)

# ---- Kubernetes ----
ansible-playbook playbook/etcd-deploy.yaml       # 外置 etcd(建议 3/5 台奇数)
ansible-playbook playbook/k8s-install.yaml       # 首 master kubeadm init + CNI + 其余 master 加入
ansible-playbook playbook/k8s-add-node.yaml      # 加 worker

# ---- 验证 ----
kubectl get nodes                                # 全部 Ready
kubectl get pod -A                               # coredns / CNI Pod Running
```

> **顺序要点**：先挂盘 → containerd → docker → harbor → etcd → k8s；docker 复用 containerd 见 [七](#七docker-与-harbor)。
> **单 / 多 master**：单 master 不设 `lbvip` 即免 LB；多 master 高可用需先配 `lbvip` + 跑 LB（[八](#八负载均衡k8s-apiserver-高可用haproxy--nginx-ha--keepalived)）。详见 [十二](#十二kubernetes-部署etcd--控制面--cni--worker)。
> **最省事验证路径**（在线单 master 最小跑通）见 [十二.1](#十二1-实机验证在线单-master-最小跑通示例)。

## 一、主机清单（inventory/hosts，INI 格式）

按角色分组，**行内**给节点设变量（`accelerator_type` / `host_ip` 等）。首次先用 `bash init.sh` 从 `tmp/hosts.example` 生成 `inventory/hosts`（已存在则跳过），再按实际填写。实际结构：

```ini
[cluster]                      # 所有节点(可带 ipmi_ip / storage_ip 等自定义变量)
node018 ansible_host=10.1.0.18

[docker]                       # 装 docker 的节点(harbor 用); accelerator_type=nvidia 装 GPU toolkit
[cri_docker_nodes]             # (cri-dockerd 已弃用,留空)

[containerd]                   # 用 containerd 的节点; accelerator_type 行内设(不指定=默认runc)
node018 accelerator_type=nvidia

[harbor]                       # Harbor 节点
10.2.0.15

[k8slb]                        # haproxy+keepalived LB 节点(用主机别名); host_ip 可省(自动按 ansible_host 探测)
10.2.0.11 host_ip=10.2.0.11
10.2.0.12 host_ip=10.2.0.12
10.2.0.13 host_ip=10.2.0.13

[etcd]                         # 外置 etcd(建议 3/5 台奇数; 单 master 可与 master 共机)
[k8s_master]                   # 控制面(单 master 放 1 台且不设 lbvip 即免 LB)
[k8s_node]                     # worker

[all:vars]                     # 全局变量: 本段只放 python 解释器 / ssh 参数
# 集群参数(chrony_ip / lbvip / vip_prefix / is_offline / kube_network_plugin 等)
# 一律在 inventory/group_vars/all/env.yaml 配置 —— group_vars 优先级高于 hosts,
# 写在 [all:vars] 会被 env.yaml 覆盖(不生效)。
# 连接身份(root 直连 / 普通用户+sudo)由 group_vars/all/connection.yaml 决定,默认 connect_as=root,
# 【不用】在这写 ansible_user / ansible_ssh_pass / ansible_become*(写了也会被 connection.yaml 覆盖);
# 首次未免密时改 connect_as=sudo 并配 bootstrap_user / bootstrap_ssh_pass / bootstrap_become_pass。
ansible_python_interpreter=/usr/bin/python3
ansible_ssh_common_args="-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null"
```

> ⚠️ `inventory/hosts` 含密码，已被 `.gitignore` 忽略、**不提交**；仓库里 `hosts` 保留注释示例（另见 `tmp/hosts.example`）。

### 连接与免密

连接身份由 `group_vars/all/connection.yaml` 决定,**默认 `connect_as: root`**（全程 root 免密直连，本项目常态）。所以 `[all:vars]` 里【不用】再写 `ansible_user`/`ansible_ssh_pass`/`ansible_become*`。

| 情况 | 怎么配 |
|---|---|
| **已 root 免密**（常态） | 默认 `connect_as: root`，什么都不用配；`bootstrap_*` 可不填 |
| **还没配 root 免密**（首次进场只有厂商账号） | 先跑 `add-control-key.yaml -k` 下发控制机公钥即可回到 root；或临时 `env.yaml` 配 `connect_as: sudo` + `bootstrap_user` / `bootstrap_ssh_pass` / `bootstrap_become_pass` 走「普通用户 + sudo」 |
| **首次引导想自动判** | `connect_as: auto` 逐台探测（免密→root，否则 用户+sudo）——仅建议引导期临时用,见下方 ⚠ |

> ⚠️ `connect_as: auto` 的探测是「group_var 里惰性跑 ssh」，在 **`delegate_to` 委派任务**（加节点/拿 join/etcd）下委派机地址解析对不齐、易误判成「用户+sudo」而报 `bootstrap_user 未定义`；也**不认堡垒机/ProxyJump**、慢节点可能 4s 超时误判。**所以默认用 `root`,委派密集的操作别用 auto**。sudo 回退需**控制机**装 `sshpass`。

## 二、配置核心变量（group_vars/all/env.yaml）

变量分两个文件（同属 `group_vars/all`，自动合并、同优先级）：
- **`env.yaml`** —— 部署新环境「要改」的，就看这一个文件；
- **`defaults.yaml`** —— 默认（镜像清单/路径/`k8s_compat`/派生变量等），一般不动。

部署新环境**主要改这几个核心变量**（其余用默认即可）：

| 变量 | 本例值 | 说明 |
|---|---|---|
| `harbor_instances` | dns: `harbor.local.clusters`, ip: `10.2.0.15` | Harbor 域名 + 地址 |
| `pause_image_version` | `3.10.1` | pause 版本(与 k8s 版本绑定); `sandbox_image` 随 `is_offline` 自动切,无需手改 |
| `containerd_version` | `1.7.32` | containerd 版本(或 `2.2.3`) |
| `runc_version` | `1.1.12` | runc 版本 |
| `container_base` | `/data` | 数据盘主挂载点 |
| `data_root` | `/data/docker` | docker 数据目录 |
| `harbor_copy_path` | `/data/harbor/harbor-install` | harbor 安装目录 |
| `data_volume` | `/data/harbor-data` | harbor 数据目录 |
| `harbor_admin_username` / `harbor_admin_password` | `admin` / `Harbor12345` | harbor 管理员(建议改密码) |

> 其它变量（镜像清单、docker_softs、nginx 路径、加速器映射等）一般用默认。完整清单见 [十](#十关键变量参考group_varsallenvyaml)。

### sandbox_image（pause 镜像）怎么定

pause 是每个 Pod 的基础容器（占网络命名空间），**版本与 k8s 版本绑定**，换 k8s 版本要跟着改。`sandbox_image` 是派生变量（`defaults.yaml`），随 `is_offline` 自动在「自建 Harbor」与「在线阿里云 mirror」之间切，正常只需改 `pause_image_version`。

1. **查目标 k8s 版本要哪个 pause**（权威，别猜）：
   ```bash
   kubeadm config images list --kubernetes-version v1.34.3 | grep pause
   # 输出如 registry.k8s.io/pause:3.10.1
   ```
   对照参考：k8s 1.28→`3.9`、1.32→`3.10`、1.34.3→`3.10.1`。

2. **离线环境**会自动指向私有 Harbor（外网 `registry.k8s.io` 拉不到）：`sandbox_image` 解析为 `{{ registry }}/pause:{{ pause_image_version }}`，`registry` 见 [十](#十关键变量参考group_varsallenvyaml)。

3. **⚠️ 必须与 kubeadm/kubelet 用的 pause 一致**，否则会拉出两个 pause / kubelet 报镜像不匹配。

## 三、SSH 免密

Ansible 能连上各节点即可跑（连接逻辑见 `connection.yaml`：root 免密直连 / 用户+sudo 回退）。想给控制机建**持久**免密,用下面这对。

### 控制机 → 各节点免密：交付前置 / 交付收尾（add / remove，推荐）

把**控制机（跑 ansible 这台）**的 root 公钥下发到全 `cluster` / 再撤除。控制机通常不在 inventory 里，需单独成对管理：

```bash
# 交付前置：把控制机 root 公钥下发到全 cluster（首次控制机还没免密时加 -k 输密码）
ansible-playbook playbook/add-control-key.yaml -k

# 交付收尾：从全 cluster 撤除控制机 root 公钥
ansible-playbook playbook/remove-control-key.yaml
```

### 单机手动配 root 本机免密（备用）
```bash
ssh-keygen -t rsa -b 4096 -f /root/.ssh/id_rsa -N ""
cat /root/.ssh/id_rsa.pub >> /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
```
> 还没 root 免密 → 在 `env.yaml` 配 `bootstrap_*`，连接自动走「用户 + sudo」；已有 root 免密 → root 直连，无需额外配置。

> **宿主机层跑多机 MPI（一台 launcher → 多台 worker）需要节点间免密时**：复用 `add-control-key.yaml`，把公钥源指到 launcher 节点即可——在 launcher 上 `ansible-playbook add-control-key.yaml -e control_pubkey_file=/root/.ssh/id_rsa.pub`。（k8s 内的多机训练走 pod 网络，不需要宿主机免密；故不再单独维护节点↔节点 N×N 互信脚本。）

- 两者精确互逆，只针对**控制机这一把** key（`lookup` 读控制机本地 `/root/.ssh/id_rsa.pub`）。公钥路径可覆盖：`-e control_pubkey_file=/path/to/id_rsa.pub`。
- ⚠️ `remove-control-key` 是**交付最后一步**：跑完控制机对各节点的免密立即失效，之后再连需要密码。务必在其它 playbook 都跑完后再执行；验证（如 `ansible cluster -m ping`）要趁免密还在时做。

## 四、系统初始化（init.yaml，在线/离线同一入口）

统一走 `init.yaml`，在线/离线由 `group_vars/all/env.yaml` 的 `is_offline` 控制（原来的 `init-offline.yaml` 已删除）：

| is_offline | 用途 |
|---|---|
| `false` | 在线：联网 yum/apt（默认）|
| `true` | **离线**：改用本地 `/opt/*-pkgs` 源 localinstall |

按发行版分流（ubuntu/kylin/openEuler/redhat），公共项在 `common.yaml`。

**离线包 + 下载脚本**（联网机生成）：

| 系统 | 离线包 | 生成脚本 |
|---|---|---|
| Ubuntu | `ios-offline/ubuntu{22,24}_{x86_64,arm64}.tar.gz` | `download_ubuntu_packages.sh` |
| Kylin | `ios-offline/kylin_{x86_64,arm64}.tar.gz` | `download_kylin_packages.sh` |
| openEuler | `ios-offline/openEuler22_{x86_64,arm64}.tar.gz` | `download_openeuler_packages.sh` |

> 脚本 docker 多架构下载，含 k8s 依赖（socat/conntrack/ipset/ebtables/chrony/ipvsadm 等）。

**⚠️ ansible 版本兼容**：Kylin V10 SP3 自带 **ansible 2.8.8**，不支持 `ansible.builtin.` FQCN。本仓库已全用**短名**模块，兼容 2.8+。**写新 role 也用短名。**

### 时间同步（chrony）
- **变量 `chrony_ip`**：NTP 服务器 IP（`group_vars/all/env.yaml` 设）
- 模板 `chrony.conf.j2` → Debian `/etc/chrony/chrony.conf`，RHEL 系 `/etc/chrony.conf`
- 服务名：Debian=`chrony`，RHEL/openEuler/Kylin=`chronyd`（自动区分）
- 验证：`chronyc sources`

### 单机快速初始化（不走 ansible）

只有一两台、或临时机器不想起 ansible 时，用 `scripts/` 下的**单机脚本**直接跑，效果等价于 init 角色的**在线**初始化（时区/br_netfilter/sysctl 调优/limits/关 swap/关防火墙+SELinux(RHEL)/装 k8s 基础依赖/chrony）。

| 脚本 | 适用 | 说明 |
|---|---|---|
| `scripts/debian-init.sh` | Debian / Ubuntu | 对齐 `debian.yaml`+`common.yaml`；含 apt 非交互、关自动更新/needrestart、禁 cloud-init 网络接管、hold 当前内核 |
| `scripts/rhel-init.sh` | CentOS/RHEL/Rocky/Alma · Kylin · openEuler | 对齐 `redhat.yaml`/`kylinsp3.yaml`/`openEuler.yaml`+`common.yaml`；按 `/etc/os-release` 自动判族分流装包（`--skip-broken`）；dnf 优先 |

```bash
sudo bash scripts/debian-init.sh                       # 默认(不改主机名, chrony 用系统默认源)
sudo bash scripts/rhel-init.sh   -H k8s-master1        # 顺便设主机名
sudo CHRONY_IP=10.0.0.1 bash scripts/rhel-init.sh      # 指定内网 NTP 上游
```

> - 面向**在线**单机（能直连 apt/yum 源）；**离线批量**仍走 ansible 的 `init.yaml`（在 env.yaml 置 `is_offline=true`，它拷 `/opt/*-pkgs` 本地 localinstall）。
> - sysctl 写 drop-in `/etc/sysctl.d/99-k8s.conf`（比覆盖 `/etc/sysctl.conf` 安全等效）；幂等可重复跑。
> - `rhel-init.sh` 对 openEuler 也统一关了防火墙/SELinux（角色本未做，但对 k8s 节点推荐且幂等安全）。
> - 跑完建议 `reboot` 一次让内核参数/limits 完全生效。

## 五、数据盘挂载

containerd 数据目录入口 = `config.toml` 的 `root`（本仓库变量 `containerd_root`，等同 docker `data-root`）。

```
数据盘 → 挂到 {{ container_base }}(默认 /data)
   ├─ containerd/  ← 走 config root(不 bind)
   └─ kubelet/     ← bind 到 /var/lib/kubelet
```

| playbook | 适用 |
|---|---|
| `mount-nvme.yaml` | 单盘 |
| `mount-nvme-lvm.yaml` | 多盘(2或4块) 自动识别空闲 NVMe → 组 LVM(条带化) |

**多盘 LVM 安全**：选盘 6 道检查(无分区/holders/blkid/wipefs/PV/挂载)，组 LVM 前必须**数量2或4 + 容量一致**，否则中止。**绝不碰有数据的盘。** 建议先 `--check --diff` 看识别结果。

**盘上有数据被拦时**（如 3.84T 盘识别不到/数量不够，是盘上有残留数据）：**先和同事确认该盘可清**，再清盘重跑：
```bash
nvme format /dev/nvme5n1 --ses=1   # ⚠️ 数据全没,务必确认无用
nvme list
```

**换盘/改路径**：换物理盘改 `device_path`；改位置改 `container_base`；LVM 内换盘用 `pvmove`。

## 六、Containerd

### 6.1 三个 role 分工
| Role | 职责 |
|---|---|
| `containerd_install` | 装二进制/runc/服务（版本感知：不符才替换） |
| `container-toolkit` | 按 `accelerator_type` 装 nvidia/dcu/npu 运行时 |
| `containerd_setup` | 生成 config.toml、certs.d、CDI、/etc/hosts |

顺序：install → toolkit → setup（见 `containerd-setup.yaml`）。

### 6.2 版本切换（只改一个变量）
```yaml
containerd_version: "1.7.32"    # 或 "2.2.3"
containerd_config_version: "{{ 3 if (containerd_version.split('.')[0] | int) >= 2 else 2 }}"
```
自动对齐：取包路径 + config 格式(v2/v3) + 模板（`config.toml.j2` v3 / `config-v2.toml.j2` v2）。

### 6.3 加速器类型
`nvidia` / `dcu` / `npu`(华为昇腾,不用 ascend) / `none`(默认)。在主机清单 INI 行内设置。

## 七、Docker 与 Harbor

**定位**：docker 只给 Harbor 用；k8s 节点用 containerd 直连，不用 cri-dockerd。

- **docker 复用已有 containerd**：docker role 检测到节点已装 containerd 时不覆盖，让 dockerd 通过 `--containerd /run/containerd/containerd.sock` 连现有的（一节点一个 containerd）。**所以先装 containerd 再装 docker。**
- **Harbor**：`ansible-playbook playbook/harbor-install.yaml`（`hosts: harbor`）。
- **域名解析**：`containerd_setup` 把 `harbor_instances` 写入 `/etc/hosts`。
- **CA 信任**：`ansible-playbook playbook/harbor-trust.yaml`（RHEL 系含 openEuler/Kylin + Debian 系），完后 `docker login harbor.local.clusters -uadmin -pHarbor12345` 验证。

Harbor/Docker 变量见 [十](#十关键变量参考group_varsallenvyaml)。

## 八、负载均衡（k8s apiserver 高可用：haproxy / nginx-ha + keepalived）

二选一：

| 方案 | playbook / hosts | 组成 |
|---|---|---|
| **haproxy-ha** | `lb-haproxy-install.yaml`，`hosts: k8slb` | haproxy(`:{{ apiserver_lb_port }}`) → master `:{{ apiserver_port }}` + keepalived VIP |
| **nginx-ha** | `lb-nginx-install.yaml`，`hosts: lb_upstream_servers` | nginx 四层(`:{{ apiserver_lb_port }}`) + keepalived VIP |

> **端口变量**（`env.yaml`）：`apiserver_port`（apiserver 本地/LB 后端，默认 `6443`）、`apiserver_lb_port`（经 VIP 访问的端口，默认 `8443`）。LB 前端、kubeadm `controlPlaneEndpoint` 统一用 `apiserver_lb_port`，改一处三处同步（修了原 haproxy `16443` 与 kubeadm `8443` 不一致的问题）。

**关键变量**：`lbvip`(VIP)、`vip_prefix`(按实际掩码) 在 `group_vars/all/env.yaml` 设(单 master 保持 `lbvip` 注释即免 LB);`[k8slb]`组(用主机别名,host_ip 可省)、`lb_upstream_servers`。
keepalived：动态 priority（节点序）+ nopreempt + VIP 派生 router_id/auth_pass + 健康检查脚本触发漂移。

```bash
ansible-playbook playbook/lb-haproxy-install.yaml   # 或 playbook/lb-nginx-install.yaml
ip a | grep <lbvip>                                 # 验证 VIP 只在优先级最高的节点
```

> LB 的移除/扩缩见 [十五](#十五扩缩容与卸载节点--etcd--底座)。

## 十二、Kubernetes 部署（etcd → 控制面 → CNI → worker）

> 前提：底座已就位（[快速上手](#快速上手命令清单)）——各节点已装 **containerd**、已配 **免密**、Harbor 可用（离线时）。
> 在线/离线：默认在线；**离线整条链路加 `-e is_offline=true`**。

主机清单需有这些组（见 [一](#一主机清单inventoryhostsini-格式)与 `tmp/hosts.example`）：`[etcd]`、`[k8s_master]`、`[k8s_node]`。

> **单 master 免 LB**：只放 1 台 `[k8s_master]`、**不设 `lbvip`** 即可，kubeadm 自动省略 `controlPlaneEndpoint`，跳过 haproxy/nginx-ha。省机器可把该 master 也写进 `[etcd]` 与 etcd 共机。
> **多 master 高可用**：必须配 `lbvip` + 跑 LB（[八](#八负载均衡k8s-apiserver-高可用haproxy--nginx-ha--keepalived)），否则 `k8s-install` 预检会直接报错（kubeadm 无稳定入口无法 join 额外 master）。

```bash
# 1. 部署外置 etcd 集群(建议 3/5 台奇数)
ansible-playbook playbook/etcd-deploy.yaml                       # 离线加 -e is_offline=true

# 2. 安装控制平面(首 master kubeadm init + CNI + 其余 master 加入)
ansible-playbook playbook/k8s-install.yaml                      # 离线加 -e is_offline=true

# 3. 加入 worker 节点
ansible-playbook playbook/k8s-add-node.yaml                     # 离线加 -e is_offline=true

# 4. 验证
kubectl get nodes                # 全部 Ready
kubectl get pod -A               # coredns / CNI Pod Running
```

**内部机制**：
- **etcd**：外置二进制 + systemd，`certs` role 用 openssl 生成 CA / 每节点证书 / apiserver-etcd-client 证书。
  > **直接用 etcdctl**：部署时已把 `etcdctl` 软链到 `/usr/local/bin` 并在 `/etc/profile.d/etcdctl.sh` 导出端点与证书环境变量。登录任一 etcd 节点即可**零参数**操作（新开 SSH 自动生效；当前会话先 `source /etc/profile.d/etcdctl.sh`）：
  > ```bash
  > etcdctl endpoint health                    # 各成员健康
  > etcdctl member list -w table               # 成员列表
  > etcdctl endpoint status --cluster -w table # leader / DB 大小 / 版本
  > ```
- **控制面**：kubeadm + external etcd；有 `lbvip` 时 `controlPlaneEndpoint={{ lbvip }}:{{ apiserver_lb_port }}`（HA）。`kubeadm-config.yaml.j2` 的 `imageRepository`、`kubernetesVersion`、端口均取变量（不再硬编码）。
- **镜像**：离线先 `docker load` 本地 tar 推 Harbor（`sync-images-to-harbor` / `sync-cni-images`，仅离线跑）；在线直接从公共 mirror 拉，跳过同步。
- **k8s 二进制**：离线从 `offline/artifacts/kubernetes/v{版本}/bin/{arch}/`；在线从 `k8s_bin_mirror` 下载。

### 十二.1 实机验证（在线单 master 最小跑通示例）

> 已实机跑通的最省事路径：1 台 master（兼 etcd）+ 1 台 worker，`is_offline=false`，calico。不用先下几十 GB 离线物料，用来验证部署流程是否通最合适。

```bash
# 依次(全在线, 不加 -e is_offline)
ansible-playbook playbook/containerd-setup.yaml     # 各节点装 containerd
ansible-playbook playbook/etcd-deploy.yaml          # 外置 etcd
ansible-playbook playbook/k8s-install.yaml          # 首 master(单 master 免 lbvip)
ansible-playbook playbook/k8s-add-node.yaml         # 加 worker
```

验证（在 master 上）：

```bash
# 1) 节点/系统 Pod
kubectl get nodes                       # 两节点都 Ready, 版本一致
kubectl get pod -A                      # coredns / calico-node 全 Running

# 2) 跨节点调度 + IPAM: 起两个 Pod 用 nodeSelector 强制分到不同节点(或直接看落点)
kubectl run t1 --image=registry.aliyuncs.com/google_containers/pause:3.10.1
kubectl run t2 --image=registry.aliyuncs.com/google_containers/pause:3.10.1
kubectl get pod -o wide t1 t2           # NODE 列应落在不同节点, IP 落在 pod_subnet 内

# 3) 跨节点连通性(关键)
#   ⚠️ pause 镜像没有 shell/ping, 不能 kubectl exec 进去互 ping;
#      改从【宿主机】ping 对端节点上的 Pod IP —— 这才验证 CNI 跨节点路由。
#   在节点 A 上: ping -c3 <落在节点 B 的 Pod IP>
#   在节点 B 上: ping -c3 <落在节点 A 的 Pod IP>
kubectl delete pod t1 t2                # 验证完清理
```

> calico 默认 `calico_encapsulation: none`（纯 BGP，需二层互通）。上面 ping 若**跨网段不通**，把 env.yaml 的 `calico_encapsulation` 改 `crosssubnet`（同子网走 BGP、跨子网才 IPIP 封装），再 `ansible-playbook playbook/k8s-cni-switch.yaml -e confirm_switch=yes` 切一下。

## 十三、CNI 切换（calico / flannel / cilium）

KubeKey 风格：**一个变量 `kube_network_plugin`** 决定装哪个（`roles/cni` 调度）。默认 `calico`。

| 插件 | 方式 | 说明 |
|---|---|---|
| `calico` | manifest（`kubectl apply`） | BGP，pod CIDR 继承 kubeadm `podSubnet` |
| `flannel` | manifest | vxlan，`net-conf.json` 的 `Network` 取 `pod_subnet` |
| `cilium` | helm chart | eBPF，`ipam=cluster-pool`；默认保留 kube-proxy、关 hubble |

```bash
# 安装时选(在 env.yaml 或 -e 指定)
ansible-playbook playbook/k8s-install.yaml -e kube_network_plugin=flannel

# 已装好的集群单独装/切 CNI(首 master 执行)
ansible-playbook playbook/k8s-cni.yaml -e kube_network_plugin=cilium
```

> ⚠️ **`k8s-cni.yaml` 只 apply,不删旧 CNI**——用于全新集群装 CNI、或清掉旧 CNI 后装新的。
> **在已装 CNI 的集群上原地换**，用 `k8s-cni-switch.yaml`（删旧 → 清节点 → 装新 → 重建 coredns）：
> ```bash
> ansible-playbook playbook/k8s-cni-switch.yaml -e kube_network_plugin=flannel -e confirm_switch=yes
> ```
> 会短暂中断网络;业务 Pod 需自行 `kubectl rollout restart`。**最干净的换法仍是 reset 重装。**
> 不要在同一集群混装多个 CNI。`cilium` 需 helm（离线内置 `offline/artifacts/helm/`,在线自动下载）。
> 可选叠加 multus:`-e enable_multus=true`。

## 十三·五、运维附加(NodeLocal DNSCache / kubelet serving 证书)

两个独立 playbook,均可对**已跑起来的集群**重复执行(幂等),互不依赖。

### NodeLocal DNSCache(每节点本地 DNS 缓存)

降 CoreDNS 压力 / 省 conntrack。查询链:Pod(clusterDNS=`169.254.25.10`)→ nodelocaldns 本地缓存 → CoreDNS。
**忠实复刻现网 KubeKey/KubeSphere 版**:DS/CM/SA 名 `nodelocaldns`,单绑 `nodelocaldns_ip`,转发到运行时查到的
CoreDNS Service(`coredns`)ClusterIP。对现网 apply 是 **reconcile 同一 DS(幂等,不新建)**。

```bash
ansible-playbook -i inventory/hosts playbook/nodelocaldns.yaml                    # 在线
ansible-playbook -i inventory/hosts playbook/nodelocaldns.yaml -e is_offline=true # 离线(需先备镜像)
# 验证
kubectl -n kube-system get ds nodelocaldns            # DESIRED==READY(全节点)
ip addr show nodelocaldns                             # 有 169.254.25.10
```

**变量(默认放 defaults.yaml,站点专属放 gitignored env.yaml):**

| 变量 | 默认 | 说明 |
|---|---|---|
| `nodelocaldns_ip` | `169.254.25.10` | 必须与各节点 kubelet `clusterDNS` 一致(现网即此值) |
| `nodelocaldns_version` | `1.26.4` | `registry.k8s.io/dns` 正规上游 tag(现网即此);换版本在 env.yaml 覆盖 |
| `nodelocaldns_image_online` | `k8s.m.daocloud.io/dns/k8s-dns-node-cache` | 在线源(= `registry.k8s.io/dns/...`,daocloud 国内加速) |
| `nodelocaldns_coredns_svc` | `coredns` | 上游 CoreDNS svc 名(kubeadm 原生叫 `kube-dns`) |
| `nodelocaldns_stub_zones` | `[]` | **站点专属→env.yaml**;每项 `{zone, forward, cache(可选30), health(可选)}` |
| `nodelocaldns_hosts` | `[]` | **站点专属→env.yaml**;`.:53` 静态解析,每项 `{ip, names:[...]}` |

env.yaml 示例(现网那两段站点定制):
```yaml
nodelocaldns_stub_zones:
  - { zone: "e2-s3.msh.team", forward: "10.200.82.49", cache: 10 }
nodelocaldns_hosts:
  - { ip: "10.82.254.130",  names: ["moonshot-registry-vpc.cn-beijing.cr.aliyuncs.com"] }
  - { ip: "10.92.33.8",     names: ["msh-m2-registry-vpc.ap-southeast-1.cr.aliyuncs.com"] }
  - { ip: "172.24.111.254", names: ["msai-cn-beijing.cr.volces.com"] }
```

> ⚠️ `nodelocaldns_ip` **必须与各节点 kubelet `clusterDNS` 一致**;不一致 Pod 会把 DNS 发往未监听 IP → 全部解析失败。
> ⚠️ 现网已在运行(名字/结构一致),apply 前建议先 `--check` 或先在测试集群验,确认渲染 manifest 与现网一致再动生产。
> 前提:kube-proxy 为 **iptables** 模式(role 内已 assert)。
> 离线镜像 `k8s-dns-node-cache` 由 `download-k8s-offline.sh` 从 `k8s.m.daocloud.io/dns`(= `registry.k8s.io/dns` 上游,daocloud 加速)拉,与组件镜像一起放 `.../kubernetes/v{k8s}/images/`。

### kubelet serving 证书(serverTLSBootstrap + 审批 kubelet-serving CSR)

现网 kubelet 10250 是自签名证书,`metrics-server`/`kubectl top`/`exec`/`logs` 需 `--kubelet-insecure-tls`。
开 `serverTLSBootstrap` 后 kubelet 向集群 CA 申请正规 serving 证书,再审批 `kubernetes.io/kubelet-serving` CSR。
新集群 kubeadm 模板已自带 `serverTLSBootstrap: true`,**本 playbook 仅用于存量集群补下发**。

```bash
ansible-playbook -i inventory/hosts playbook/kubelet-serving-cert.yaml   # 全节点(master+worker)
# 验证
kubectl get csr | grep kubelet-serving                                   # Approved,Issued
openssl s_client -connect 127.0.0.1:10250 </dev/null 2>/dev/null | openssl x509 -noout -issuer -ext subjectAltName
```

> 全节点幂等下发(`lineinfile` 替 sed);顺带 patch `kubelet-config` ConfigMap → 新节点 join / kubeadm upgrade 不丢;
> CSR 自动审批**只批 signer=kubelet-serving 且请求者是已知 inventory 节点**,不误批。
> 证书到期(kube-controller-manager `--cluster-signing-duration`,默认 1y)重签会再产 CSR,重跑本 playbook 即可。

## 十四、多版本 K8s 与国内镜像

**多版本**：`k8s_version` 是唯一真源（同 `containerd_version` 思路），改一处即切换。版本变量分两组：

- **A 组（跟 k8s 版本走，基本不用管）**：`coredns` / `pause` / `crictl`。装 k8s 时 playbook 会**自动跑 `kubeadm config images list --kubernetes-version v{{ k8s_version }}` 拿权威值**覆盖，不用手查。`k8s_compat` 矩阵只做两件事：① containerd 的 sandbox(pause) 镜像（k8s 装之前就要用，来不及查）；② 查不到时的兜底默认。当前只列在用的 **1.28 / 1.34** 两支；起新版本（如 1.35）装时会自动查，若 pause 变号再加一行。
- **B 组（独立选，跟 k8s 无关）**：`etcd` / `calico` / `flannel` / `cilium` / `helm`——这些按各自的 k8s 兼容矩阵挑，不从 k8s 版本推。

> 换 k8s 版本正常只改 `k8s_version` 一处即可；A 组自动对齐（在线 kubeadm 自己选，离线由上面的自动查询对齐 tar）。

> **etcd 与 kubeadm 的一致性校验**：etcd 是**外置二进制集群**，由 `etcd-deploy.yaml` 先于控制面单独部署（那时机器上还没 kubeadm 可查），所以它**没法像 A 组那样自动填充**，`etcd_version` 仍在 env.yaml 手钉。但装控制面时（`kubeadm config images list` 已可跑），playbook 会拿 kubeadm 推荐的 etcd tag（剥 `-N` 后缀）与已部署的 `etcd_version` 比对：一致打 ✓，漂移打 ⚠（外置 etcd 独立运维、比推荐补丁号新是允许的，默认只告警不拦）。想让漂移直接失败，env.yaml 设 `etcd_version_strict: true`。
> 下载侧（`download-k8s-offline.sh`）的 etcd 版本本就已从 kubeadm 自动校准（section 1.5，`3.6.8-0 → 3.6.8`），无需手动。

- 离线包按版本分目录：`offline/artifacts/kubernetes/v{{ k8s_version }}/{bin,images}/{amd64,arm64}/`；想并存多版本就放多个 `v1.32.10/`、`v1.34.3/`，切版本只改变量。
- 在线二进制从 `k8s_bin_mirror/v{{ k8s_version }}/bin/linux/{arch}/` 下载。

**官网受限 → 国内镜像**（全部变量化，默认已指国内，可随意改）：

| 变量 | 默认 | 用途 |
|---|---|---|
| `kube_image_repository` | 离线自建 Harbor / 在线 `registry.aliyuncs.com/google_containers` | kubeadm 组件镜像（`is_offline` 自动切） |
| `kube_image_mirror` | `registry.aliyuncs.com/google_containers` | 在线组件镜像 mirror |
| `calico_registry_online` / `flannel_registry_online` / `cilium_registry_online` | docker.io/calico、docker.io/flannel、quay.io/cilium | 在线 CNI 镜像仓（受限可换国内 mirror） |
| `k8s_bin_mirror` | `https://dl.k8s.io/release` | 在线下载 kubeadm/kubectl/kubelet（国内可换阿里云镜像） |

## 十五、扩缩容与卸载（节点 / etcd / 底座）

> **加节点：只「加」新节点到清单，别注释老的**。inventory 里 `[cluster]`/`[containerd]`/`[k8s_node]`(或 `[k8s_master]`) 各加一行新节点即可。示例（新增 cpu220 worker）：
> ```bash
> ansible-playbook playbook/init.yaml             --limit cpu220   # ★ 必须 --limit
> ansible-playbook playbook/mount-nvme.yaml       --limit cpu220   # ★ 必须 --limit(按需)
> ansible-playbook playbook/containerd-setup.yaml --limit cpu220   # ★ 必须 --limit
> ansible-playbook playbook/k8s-add-node.yaml                      # 可不加(见下)
> ```
> **`--limit` 什么时候必须**：
> - **`init` / `containerd-setup` / `mount-nvme`（底座）→ 必须 `--limit 新节点`**。它们作用于 `cluster`/`containerd` 组，不限制会在老节点重跑、**重启 containerd 扰动运行中的 Pod**。
> - **`k8s-add-node` / `k8s-add-master` / `k8s-install`（k8s 层）→ 可不加**。已加入的节点会 `meta: end_host` 自动早停，`kube-common` 对老节点幂等无重启，全跑也安全（`--limit` 只是更快）。
> - 加 master 同理：新节点进 `[k8s_master]`，`k8s-add-master.yaml`(可选 `--limit`)。加多台 `--limit 'cpu220,cpu221'`。

```bash
# ---- worker ----
ansible-playbook playbook/k8s-add-node.yaml                     # 加(填 [k8s_node] 新节点)
ansible-playbook playbook/k8s-del-node.yaml                     # 删(填 [node_to_delete])

# ---- master ----
ansible-playbook playbook/k8s-add-master.yaml                   # 加(填 [master_to_add])

# ---- etcd ----
ansible-playbook playbook/etcd-scale-up.yaml                     # 扩(填 [etcd_to_add])
ansible-playbook playbook/etcd-scale-down.yaml                   # 缩(填 [etcd_to_delete],保护:剩余<2 中止)
ansible-playbook playbook/etcd-config-update.yaml               # 同步 etcd 配置
ansible-playbook playbook/etcd-destroy.yaml                      # 销毁 etcd(慎用)

# ---- 整集群重置(重装前清场) ----
ansible-playbook playbook/k8s-reset.yaml -e confirm_reset=yes   # 所有 master+worker kubeadm reset+清理
#   默认同时清空外置 etcd 数据(否则重装会撞旧数据); 想保留 etcd 数据加 -e reset_etcd=false
```

> `k8s-reset.yaml` 是破坏性操作，**必须加 `-e confirm_reset=yes`** 才执行。它对 `[k8s_master]`+`[k8s_node]` 跑 `kubeadm reset` + 清目录/CNI 网卡/iptables，并默认销毁 `[etcd]`（用 `etcd-destroy`;外置 etcd `kubeadm reset` 不会清,不清则重装会撞旧数据）。清完即可重新 `k8s-install`。

### 底座卸载

```bash
ansible-playbook playbook/containerd-remove.yaml --limit <节点>                               # 保留配置/数据
ansible-playbook playbook/containerd-remove.yaml --limit <节点> -e purge_containerd_data=true # 彻底清
```
其它：`docker-remove.yaml` / `harbor-remove.yaml` / `lb-nginx-remove.yaml` / `lb-haproxy-remove.yaml`。

## 十六、离线部署（完整流程）

无外网环境部署。核心：**`is_offline=true` 全链路 + 物料提前打包 + 镜像走自建 Harbor 中转**。

### 1. 联网机打包物料

在**有网 + 有 docker** 的机器上（可与内网不同架构，脚本拉双架构）：

```bash
# ansible 自身离线包(内网机器没装 ansible 时先做; 取各系统当前最新版, 双架构)
bash scripts/offline/download-ansible-offline.sh        # 或指定 kylin / ubuntu / openeuler
# OS 基础包(按发行版)
bash scripts/offline/download_ubuntu_packages.sh      # 或 kylin / openeuler
# k8s 层物料(k8s二进制/组件镜像/etcd/CNI镜像/helm+cilium chart, 双架构)
bash scripts/offline/download-k8s-offline.sh
# 底座运行时 + docker 层(containerd/runc + docker静态包 + buildx + compose + cri-dockerd, 双架构)
bash scripts/offline/download-docker-offline.sh
# NVIDIA GPU(nvidia-container-toolkit rpm+deb; DCU/NPU 厂商私有需手动放包)
bash scripts/offline/download-gpu-offline.sh            # 仅 amd64(GPU 节点基本都是 x86)
# harbor 物料(12 个 goharbor 组件镜像 + docker-compose, 仅 amd64)
bash scripts/offline/download-harbor-offline.sh
```

> **单架构集群省一半体积/时间**：以上 `download-ansible-offline.sh` / `download-k8s-offline.sh` / `download-docker-offline.sh` 均默认双架构(`all`)，可加架构参数只下一份 —— 纯 x86 集群用 `amd64`、纯 arm 集群用 `arm64`。
> ```bash
> bash scripts/offline/download-k8s-offline.sh amd64
> bash scripts/offline/download-docker-offline.sh amd64
> bash scripts/offline/download-ansible-offline.sh all amd64   # 第1参=发行版, 第2参=架构
> ```
> 大头在 k8s 组件/CNI 镜像(每镜像每架构各存一份 `.tar.gz`)，单架构基本减半。混合架构集群(x86 master + arm worker)或以后要加异构节点，保持默认 `all`。GPU 脚本只出 amd64(GPU 节点基本都是 x86;arm64+N 卡如 GH200/Jetson 属少数平台，本项目不覆盖)。
>
> **单架构只需命令行加参数，不用改任何配置/变量**：
> - 参数填的是**目标集群机器**的架构，不是下载机的架构 —— 纯 arm 集群哪怕在 x86 机上下也填 `arm64`(脚本用 skopeo `--override-arch` / docker `--platform` 精确拉，不看下载机)。
> - **部署侧(ansible)无需任何架构配置**：roles 靠 `ansible_architecture` 自动判架构选对应文件，你下了哪份就自动对上。
> - 结论:**双架构=默认什么都不做；单架构才需要多打一个 `amd64`/`arm64`**。只在确定集群纯单架构时才加。

`download-ansible-offline.sh` 调用 `download_{kylin,openeuler,ubuntu}_ansible.sh`(容器内 `yum install --downloadonly` / `apt install --download-only`,只抓 **ansible + 目标机缺失的依赖**,不再拉整棵依赖树),产物 `offline/ansible-pkg-install/ansible_<系统><版本>_<arch>.tar.gz`。

内网机器装 ansible **直接跑 `bash scripts/install_ansible.sh`**——它自动识别本机**系统**(kylin/openEuler/ubuntu,ubuntu 再分 22/24)与**架构**(x86_64/arm64),选对应 tar 离线安装(RHEL 系 `yum localinstall`、Debian 系 `dpkg -i`),兼容带顶层目录/平铺两种打包,装完校验 `ansible --version`。默认会在 `scripts/ansible-pkg-install`、仓库 `offline/ansible-pkg-install` 里找包;都不在时指定目录:`bash scripts/install_ansible.sh <离线包目录>`。手动装则解压后 `cd` 进目录 `rpm -Uvh --force ./*.rpm`(RHEL 系) 或 `dpkg -i ./*.deb`(Debian 系,跑两遍解顺序)。

`download-k8s-offline.sh` 特性：源走 **daocloud**（`files.m.daocloud.io`，国内快）；**双架构**（amd64/arm64）；pull 重试 + **断点续传**（已下好的跳过）；下载**大小校验**、镜像 tar 完整性校验，残缺自动重下。顶部变量可改版本/裁剪 `CNIS`。

> ⚠️ `coredns`/`pause` 版本脚本里写死，换 k8s 版本前用 `kubeadm config images list --kubernetes-version vX.Y.Z` 核对改顶部变量。

`download-harbor-offline.sh` 用 skopeo 按 amd64 拉 12 个 goharbor 组件镜像(v2.11.2)存成 `harbor/x86/<组件>-v2.11.2.tar.gz`(对齐 `harbor_offline_images`)+ `docker-compose.x86`。**仅 amd64**：goharbor 官方无任何版本的 arm64 镜像([多架构 PR 仍 stalled](https://github.com/goharbor/harbor/pull/21825))。arm64(`harbor_images_aarch64`,v2.13.0)来自 [octohelm/harbor](https://github.com/octohelm/harbor) 的现成多架构镜像(`ghcr.io/octohelm/harbor/<组件>:v2.13.0`,国内可走 `ghcr.m.daocloud.io`),复用已做好的那批 tar 即可,本脚本不代下。

打包完把整个仓库（含 `offline/artifacts/`）拷进内网。物料目录结构见 [九](#九离线二进制目录结构)。

### 2. 打开离线开关

`inventory/hosts` 的 `[all:vars]` 设一次（全链路生效，免每条 `-e`）：
```ini
[all:vars]
is_offline=true
```
效果：OS 包走本地 repo；`sandbox_image`/`kube_image_repository` 指自建 Harbor；CNI 镜像本地 tar 推 Harbor；二进制全来自离线包（在线下载 mirror 变量不生效）。

### 3. 部署顺序（离线）

```bash
bash init.sh                                    # 生成 inventory/hosts + env.yaml,填好
ansible-playbook playbook/add-control-key.yaml  # (可选)控制机→各节点免密(首次加 -k)
ansible-playbook playbook/init.yaml             # env.yaml 置 is_offline=true -> 走离线包
ansible-playbook playbook/mount-nvme.yaml        # 按需
ansible-playbook playbook/containerd-setup.yaml # sandbox=Harbor
ansible-playbook playbook/docker-install.yaml
ansible-playbook playbook/harbor-install.yaml   # ★ Harbor 必须先起(离线镜像中转站)
ansible-playbook playbook/harbor-trust.yaml
ansible-playbook playbook/etcd-deploy.yaml
ansible-playbook playbook/k8s-install.yaml      # 载入 k8s/CNI 镜像->推 Harbor->kubeadm init
ansible-playbook playbook/k8s-add-node.yaml
```

### 4. 关键点 / 坑

- **`is_offline` 全链路一致**：要么 `[all:vars]` 设一次，要么每条都 `-e is_offline=true`，**别混**（在线装的 containerd sandbox=aliyun，再离线跑 k8s 会对不上）。
- **Harbor 必须在 k8s-install 之前就绪**——离线时 k8s 组件/CNI/pause 镜像全从本地 tar `docker load` 后推 Harbor，kubeadm/CNI 再从 Harbor 拉。顺序：containerd → docker → **harbor** → etcd → k8s。
- **镜像 tar 命名**要和 sync 期望对齐（打包脚本已对齐，自己加镜像时注意）。
- **CNI 选谁备谁**：calico 只需 3 个 tar；cilium 另需 helm 二进制 + chart .tgz。
- **要测离线但机器其实有网**也行，`is_offline=true` 就不走外网。想在已在线跑起来的集群上验证离线，**必须先 `k8s-reset` 重置再整链离线**，不能直接叠加。

## 十七、常见问题排查

按「现象 → 原因 → 解法」速查。多数已在代码里修好，这里备查。

### 部署/环境
| 现象 | 原因 | 解法 |
|---|---|---|
| `init.sh: $'\r': 未找到命令` / 语法错误 | 脚本被 checkout 成 CRLF(Windows/autocrlf) | `sed -i 's/\r$//' init.sh`;仓库已加 `.gitattributes eol=lf`,新 clone 无此问题 |
| `git pull` 报 env.yaml 冲突 | env.yaml 曾被跟踪 | 已改为 init.sh 生成 + gitignore;`git stash && git pull && git stash pop` 一次即可 |
| kubeadm 二进制 404(如 v1.34.10) | 版本号不存在 | 用真实版本(`curl https://dl.k8s.io/release/stable-1.34.txt` 查);换 minor 记得在 `k8s_compat` 加行 |

### etcd / 控制面
| 现象 | 原因 | 解法 |
|---|---|---|
| etcd raft 起不来 `tls: "VIP" does not match SAN` | keepalived VIP 与 etcd 共机, peer 出站源 IP 变 VIP, 证书 SAN 无 VIP | certs 已把 `lbvip` 加进 SAN;删旧证书(`roles/certs/files/etcd-*`)重生成 |
| kubelet 起不来 `Align by socket is not compatible...` | `cpuManagerPolicy=static`+align 在 sockets>NUMA 机器(虚机)崩 | env.yaml `kubelet_cpu_manager_policy: none`(默认已是) |
| kubeadm `pause ... not found` | sandbox_image 路径/版本与 sync/kubeadm 不一致 | 已统一为 `registry`(unisound) + `pause_image_version`(k8s_compat/kubeadm 权威) |
| 节点 NotReady `cni plugin not initialized` | reset 删了 /etc/cni, containerd fsnotify 失效 | k8s-reset 末尾已重建目录 + 重启 containerd;手动则 `systemctl restart containerd` |

### 离线镜像
| 现象 | 原因 | 解法 |
|---|---|---|
| `docker save` 多架构报 `content digest not found` | docker 导 --platform 拉的多架构镜像不可靠 | 打包改用 **skopeo**(`download-k8s-offline.sh` 已是) |
| arm64 的 tar 内容是 amd64(digest 相同) | `docker pull --platform` 复用了缓存 | skopeo `--override-arch` 精确抓(已改) |
| `docker manifest push: artifact ... not found` | 本地 `~/.docker/manifests` 脏缓存(多次失败残留) | `rm -rf ~/.docker/manifests` 再拼;或用 `docker buildx imagetools create` |
| 拉 docker.io/quay.io 超时/EOF | 国内直连不稳 | 源换国内: 镜像 `docker.m.daocloud.io`/`quay.m.daocloud.io`;二进制 `files.m.daocloud.io`(脚本已默认) |

### 扩缩容
| 现象 | 原因 | 解法 |
|---|---|---|
| 加节点要注释老清单 | 误以为必须 | **不用**:只加新节点行 + `--limit`;底座(init/containerd)必须 `--limit`,k8s-add-* 可省(end_host 早停) |
| 重跑 k8s-install 刷一屏 skip / 去污点假报错 | 幂等没做净 | 已修:已加入节点 `end_host` 早停;去污点 `\|\| true` 幂等 |
| 删节点后残留二进制/网卡/iptables | 旧 del-node 清理单薄 | 已复用 `kube-reset` 全套清理 |
