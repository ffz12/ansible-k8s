# 命令清单

`playbook/` 下有 60 来个文件，平时真正会用的是下面常用的那些。每条都能加 `--check --diff` 先预览、加 `--limit <机器>` 收窄范围。

危险等级说明：

- 🟢 只读或只改配置，跑错了影响小
- 🟡 会重启服务，业务有秒级到分钟级中断
- 🔴 会删数据或清盘，不可逆，跑之前必须 `--check`

## 一、装一套新集群（按顺序）

| 顺序 | 命令 | 作用 | 跑哪些机器 | 等级 |
|---|---|---|---|---|
| 0 | `bash init.sh` | 生成 `inventory/hosts` 和 `env.yaml`（已存在则跳过） | 控制机 | 🟢 |
| 1 | `ansible-playbook playbook/add-control-key.yaml` | 下发控制机免密公钥 | 全部 | 🟢 |
| 2 | `ansible-playbook playbook/init.yaml` | 系统初始化：内核模块、sysctl、时间同步、关 swap、装基础包 | `[init]` | 🟡 |
| 3 | `ansible-playbook playbook/mount-disk.yaml` | 挂数据盘（每块盘直接格式化挂载） | `[disk_direct]` | 🔴 |
| 3' | `ansible-playbook playbook/mount-disk-lvm-containerfs.yaml` | 4 块同容量盘组 LVM 条带 | `[disk_lvm]` | 🔴 |
| 4 | `ansible-playbook playbook/harbor-install.yaml` | 装 Harbor（1 台单节点，2 台双主） | `[harbor]` | 🟡 |
| 5 | `ansible-playbook playbook/harbor-trust.yaml` | 各节点信任 Harbor 自签 CA | docker + containerd | 🟡 |
| 6 | `ansible-playbook playbook/containerd-setup.yaml` | 装配置 containerd | `[containerd]` | 🟡 |
| 7 | `ansible-playbook playbook/etcd-deploy.yaml` | 装外置 etcd 集群 | `[etcd]` | 🟡 |
| 8 | `ansible-playbook playbook/lb-scale.yaml` | 装 LB（多 master 才需要） | `[k8slb]` | 🟡 |
| 9 | `ansible-playbook playbook/k8s-install.yaml` | 装 k8s：二进制、首台 master init、其余 master join、CNI | `[k8s_master]` | 🟡 |
| 10 | `ansible-playbook playbook/k8s-add-node.yaml` | worker 加入集群 | `[k8s_node]` | 🟡 |
| 11 | `ansible-playbook playbook/device-plugin.yaml` | GPU / RDMA 资源上报 | 首台 master | 🟢 |
| 12 | `ansible-playbook playbook/monitor.yaml` | dcgm-exporter（GPU 指标） | 首台 master | 🟢 |

在线 / 离线由 `env.yaml` 的 `is_offline` 决定，命令里不用加 `-e is_offline=true`。离线部署前先在联网机上跑 `scripts/offline/download-*-offline.sh`，再把 `offline/` rsync 到控制机。

## 五、手工删 master

没做成 playbook：删 master 是低频操作，每次状态都不一样（是不是最后一个 etcd 成员、LB 要不要同时摘），顺序错了影响 quorum，手工做看得清每一步。

按这个顺序：

```bash
# 1. 先摘 etcd 成员(外置 etcd 的 master 通常也是 etcd 成员)
#    inventory 的 [etcd_to_delete] 填这台, 然后:
ansible-playbook playbook/etcd-scale-down.yaml
#    确认: etcdctl member list 里已经没有它

# 2. 从 k8s 里删节点
kubectl drain <master名> --ignore-daemonsets --delete-emptydir-data
kubectl delete node <master名>

# 3. 那台机器上重置
ansible-playbook playbook/k8s-reset.yaml --limit <master名>

# 4. 清掉 kubeadm-config 里残留的 APIEndpoints 条目(可选)
kubectl -n kube-system edit cm kubeadm-config
#    不清只影响以后再加 master 时的提示, 不影响运行

# 5. 摘 LB 后端(这台在 [k8slb] 里才需要)
#    inventory 的 [master_to_delete] 填这台, 然后:
ansible-playbook playbook/lb-scale-remove.yaml

# 6. inventory 里删掉这台的行([cluster]/[k8s_master]/[containerd]/[etcd] 等)
```

**顺序不能颠倒**：先 reset 了 master、etcd 成员还挂在列表里的话，quorum 会按错误的成员数算。3 台 master 删到 2 台时尤其注意——etcd 从 3 成员变 2 成员，容错能力降到 0，这期间任何一台挂了集群就不可用。

## 六、少用 / 内部

平时不用，列在这里便于查。

| 命令 | 什么时候用 |
|---|---|
| `playbook/k8s-init-master.yaml` | 只初始化首台 master，`k8s-install.yaml` 内部会调 |
| `playbook/host-set.yaml` | 写 `/etc/hosts` 集群解析 |
| `playbook/host-ceph-set.yaml` | 写 Ceph 存储网的 `/etc/hosts` |
| `playbook/ceph-install.yaml`、`ceph-storage-net.yaml`、`cephfs-client.yaml` | Ceph 相关，见 `docs/ceph.md` |
| `playbook/gpu-init.yaml`、`gpu-update.yaml` | 装 GPU 驱动、升内核。用 `[gpu_driver]` 组，已交付的 GPU 节点不要放进去 |
| `playbook/os-init.yaml` | 交付项目有统一基线要求时才用，见 `docs/主机初始化-os-init.md` |
| `playbook/set-root-password.yaml` | 批量改 root 密码 |
| `playbook/apt-proxy.yaml` | 配 apt 代理（机房有 squid 之类才需要） |
| `playbook/change-yum.yaml` | 换 yum 源 |
| `playbook/cri-dockerd.yaml` | 用 cri-dockerd 的特殊场景 |
| `playbook/docker-install.yaml`、`docker-set.yaml` | 单独装 docker（本项目 docker 只给 Harbor 用） |
| `playbook/lb-haproxy-install.yaml`、`lb-haproxy-scale.yaml`、`lb-haproxy-scale-remove.yaml` | haproxy 单独操作，一般用 `lb-scale.yaml` 统一入口 |
| `playbook/lb-nginx-install.yaml`、`lb-nginx-remove.yaml` | nginx 形态的 LB（默认用 haproxy） |
| `playbook/gen-offline-versions.yaml` | 从 ansible 变量生成 `scripts/offline/versions.env`，离线下载脚本读它 |
| `playbook/mount-disk-lvm.yaml` | 2 或 4 块盘组 LVM（不是交付标准的 4 盘 containerfs 场景） |
| `playbook/mount-nvme*.yaml` | 旧文件名，转发到 `mount-disk*.yaml`，老命令兼容用 |

## 七、通用参数

| 参数 | 作用 |
|---|---|
| `--check --diff` | 预览，不实际改。挂盘、换 CNI 这类 🔴 操作跑之前务必先过一遍 |
| `--limit <机器或组>` | 收窄到指定机器。加节点时建议叠加，避免动到老节点 |
| `--tags <标签>` | 只跑某一部分，如 `init.yaml --tags dns` |
| `--list-tags` | 看有哪些标签。⚠ 动态 include 的任务只在 `--limit` 命中时才显示 |
| `-e <变量>=<值>` | 临时覆盖变量，优先级最高 |
| `--step` | 逐步确认，每个任务前停一下 |
