### 配置br0和bond
|模式 |名称 |特点|是否需要交换机配合 |
|:--|:--|:--|:--|
|0 |balance-rr（轮询）|逐个包轮流从不同网卡发，理论上可聚合带宽|❌ 不需要，但大多数交换机不支持，易丢包|
|1 |active-backup（主备）|只有一个网卡工作，另一个 standby，故障自动切换|❌ 不需要，最简单可靠|
|3|802.3ad（LACP）|动态链路聚合，真正聚合带宽+冗余|✅ 需要交换机开启 LACP|
|其他|如 balance-xor, broadcast 等|特定用途，较少用|   |
```bash
#配置网卡
cat 90-network.yaml
network:
    ethernets:
      enp1s0: {}
      enp7s0: {}
    bonds:
      bond0:
       interfaces:
        - enp1s0
        - enp7s0
       parameters:
        mode: active-backup
    bridges:
     br0:
      interfaces:
      - bond0
      addresses: [192.168.1.63/24]
      routes:
        - to: default
          # 网关 对应宿主机提供的IP
          via: 192.168.1.1
      nameservers:
        addresses: [114.114.114.114]

    version: 2
 
#加载配置
```

```bash
#!/bin/bash
 
for i in /data /baykal /home
do
   if [ ! -d $i ]; then
      echo "$i is not will create..."
      mkdir $i
   else
      echo "$i has create..."
   fi
 
done
 
 
echo "磁盘格式化"
 
mkfs.xfs /dev/nvme0n1
 
echo "挂载开机自启动脚本配置"
 
tee /etc/systemd/system/mount-remote-nfs.service <<eof
[Unit]
Description=Wait until nw actually online
[Service]
Type=oneshot
ExecStart=/usr/bin/mount -t nfs 127.x.x.x:/data /data
RemainAfterExit=yes
[Install]
WantedBy=multi-user.target
eof

[Unit]
Description=Wait until nw actually online

[Install]
WantedBy=multi-user.target
eof

[Unit]

RemainAfterExit=yes
[Install]
WantedBy=multi-user.target
eof
```

# 3. NFS相关
```bash
一、服务端安装与配置
1、在服务端安装nfs服务端组件
  
sudo apt install nfs-kernel-server  -y
   
centos ： yum install nfs-utils -y
2、创建共享目录share并且授权所有人可以访问
  
mkdir /15nfs-data/nfs-data
chmod -R 777 /15nfs-data/nfs-data
  
3、配置nfs
  
vim /etc/exports
   
这将允许127.x.x.0网段的主机以RW模式访问共享目录
  
/15nfs-data/nfs-data   127.x.x.0/24(rw,sync,all_squash)
  
4、重新加载配置、重启服务
  
exportfs -arv
  
systemctl restart nfs-kernel-server
   
centos：
systemctl restart nfs
  
5、查看共享目录
  
showmount -e localhost
  
看到了自己设置的共享目录则认为成功：
   
Export list for localhost:
/15nfs-data/nfs-data 17.x.x0/24
  
二、客户端安装与配置
  
1、安装客户端NFS组件
  
sudo apt install nfs-common -y
  
2、挂载共享目录到客户端
首先，创建一个用于挂载的目录。
  
sudo mkdir /mnt/shared
  
然后，使用以下命令将NFS共享挂载到该目录：
  
mount server_ip:/15nfs-data/nfs-data  /mnt/shared
 
```

```bash
rootless与现有环境对比：
rootless优点：

docker原生，不需要修改代码，直接运行
资源隔离，用户自己维护docker服务
避免特权提升及兼容Linux用户命名空间
文件系统隔离，默认使用  ~/.local/share/docker 存储数据，data-root自行修改
docker 配置文件在~/.config/docker/daemon.json下
现有环境优点：

普通用户目录权限完整
默认数据存储在/var/lib/docker下

rootless缺点：

多组用户的gid只能为一个，若gid未正确设置，卸载后得重启服务器然后再重新安装

 

现有环境缺点：

需要修改代码及编译，代码耦合性过高
用户构建镜像时，可能写其他人uid，gid可能导致权限泄露

 

参考链接：

https://docs.docker.com/engine/security/rootless/#tips-for-debugging
```

```bash
#!/bin/bash
function ips(){
    local nics=$(route -n | grep ^0.0.0.0 | awk '{print $8}')
    for nic in $nics
    do
        local ip=$(ifconfig $nic | grep -E 'inet\s+' | sed -E -e 's/inet\s+\S+://g' | awk '{print $2}')
        echo $ip $nic
    # 使用ethtool命令查询网卡的速率
    rate=$(ethtool  $nic 2>/dev/null |grep Speed| grep "10000" | wc -l)
    #ethtool enp129s0f0 | grep Speed|grep 10000 |wc -l
    if [ $rate -gt 0 ]; then
       echo "$nic 是万兆网卡。"
    else
       echo "$nic 不是万兆网卡。"
    fi
    done
    echo $(ethtool  $nic 2>/dev/null |grep Speed)
}
```

```bash
raid1取消

1. 检查当前的RAID状态
首先，你需要查看当前的RAID配置和状态。你可以使用mdadm命令来查看所有RAID阵列的信息：
 
 
sudo mdadm --detail /dev/mdX
 
将/dev/mdX替换为你的RAID设备的实际名称，例如/dev/md0。
2. 停止RAID阵列
在取消RAID之前，确保先停止阵列。这可以通过停止设备来实现：
 
sudo mdadm --stop /dev/mdX
 
3. 移除RAID设备
一旦RAID阵列停止，你可以从mdadm的配置中移除它。首先，你需要编辑/etc/mdadm.conf文件（或者使用mdadm --detail --scan >> /etc/mdadm/mdadm.conf来自动更新配置）：
 
sudo nano /etc/mdadm.conf
 
找到对应的RAID配置行，将其注释掉或删除。例如：
 
# ARRAY /dev/md0 level=raid1 num-devices=2 UUID=your-uuid devices=/dev/sda1,/dev/sdb1
 
保存并关闭文件。
4. 删除阵列的设备文件
在Linux中，RAID设备通常被表示为/dev/mdX。你可以通过删除这些设备文件来彻底移除RAID：
 
sudo mdadm --zero-superblock /dev/sda1
sudo mdadm --zero-superblock /dev/sdb1
 
这将清除设备上的RAID元数据，使其不再被识别为RAID设备。
5. 格式化和挂载原始磁盘（如果需要）
如果你不再需要这些磁盘作为镜像的一部分，可以选择格式化它们：
 
sudo mkfs.ext4 /dev/sda1
sudo mkfs.ext4 /dev/sdb1
 
 
然后，你可以挂载这些磁盘：
 
 
 
sudo mount /dev/sda1 /mnt/disk1
sudo mount /dev/sdb1 /mnt/disk2
 
 
 
 
6. 更新fstab（如果需要）
如果你之前将它们挂载在某个目录下，并且已经在fstab中配置了自动挂载，那么你可能需要更新或删除这些条目：
 
 
 
sudo nano /etc/fstab
 
 
 
 
删除或注释掉相关的行，然后保存并关闭文件。
7. 重启系统（可选）
为了确保所有更改生效，你可以重启系统：
 
 
 
sudo reboot
```
