# 主机清单说明（inventory/hosts）

`bash init.sh` 会从 `tmp/hosts.example` 生成 `inventory/hosts`（已存在则跳过）。`inventory/hosts` 在 `.gitignore` 里，不入库。

## 基本约定

- 机器只在 `[cluster]` 写一次，带 `ansible_host` 等变量；其它组只列主机名，同名即同一台。
- 组留空时，对应 playbook 匹配不到主机，直接跳过，不会误操作全集群。
- 集群级参数（`is_offline`、`lbvip` 等）写在 `group_vars/all/env.yaml`，不要写在 `[all:vars]`：后者优先级低于 env.yaml，会被覆盖。
- 连接身份（root 直连或普通用户加 sudo）由 `group_vars/all/connection.yaml` 决定，不要在这里写 `ansible_user` / `ansible_ssh_pass`。

## 机器行变量（写在 `[cluster]` 的机器行上）

| 变量 | 作用 | 示例 |
|---|---|---|
| `ansible_host` | SSH 地址，必填 | `ansible_host=172.171.1.201` |
| `kube_node_ip` | k8s InternalIP。不写时默认等于 `ansible_host`；多网卡、要用另一个地址时才写 | `kube_node_ip=172.18.1.66` |
| `accelerator_type` | `nvidia` / `dcu` / `npu` / `cpu`。决定装哪种容器运行时、Calico 双池分到哪个池（`hardware=gpu/cpu`），以及业务标签（`nvidia=true` / `cpu_node=true`）。**GPU 机必须写**，不写会按 CPU 机装，不装 GPU 运行时。CPU 机写 `cpu` 才打 `cpu_node=true`；不写运行时和分池跟 `cpu` 一样，只是不打这个标签 | `accelerator_type=nvidia` |
| `calico_pool` | 只覆盖 Calico 分池（`gpu` / `cpu`），不影响运行时 | `calico_pool=gpu` |
| `node_labels` | 额外的 k8s 节点标签 | `node_labels="{'gpu.model': 'b300'}"` |
| `init_config_dns` / `dns` | 按机器配 DNS，多个用逗号分隔，一次 init 跑完（只对 Ubuntu/Debian 生效） | `init_config_dns=true dns=223.5.5.5,114.114.114.114` |
| `device_path` | 单盘挂载的第一块盘，默认 `/dev/nvme2n1` | `device_path=/dev/nvme0n1` |
| `data_disks` | 额外数据盘，`盘符:挂载点`，逗号分隔，挂载点省略默认 `/data` | `data_disks="/dev/nvme1n1:/data,/dev/nvme3n1:/data2"` |
| `storage_ip` / `storage_iface` | Ceph 存储网 IP 与网卡名 | `storage_ip=172.18.104.11 storage_iface=ens46np0` |
| `osinit_su` | os-init 按 `GPU-SUx-xxx` 命名时 GPU 机的 SU 号 | `osinit_su=1` |

> `hardware` 标签只在节点首次加入时打。存量节点事后开 Calico 双池，要手工补：`kubectl label node <名> hardware=gpu --overwrite`。

## DNS：有的机器配、有的不配

默认 `init_config_dns: false`，不动系统原有 DNS。三种写法按情况选：

1. **只有少数机器要配**：在这些机器行上打开。

   ```ini
   gpu-001 ansible_host=... init_config_dns=true dns=10.14.73.1
   cpu-001 ansible_host=... init_config_dns=true dns=223.5.5.5,114.114.114.114
   ```

2. **大多数机器要配**：env.yaml 里设 `init_config_dns: true` 和公共的 `dns`，不需要的机器行上写 `init_config_dns=false`。

3. **同一组机器 DNS 一样**：写在 `inventory/group_vars/<组名>.yaml`，例如 `inventory/group_vars/gpu.yaml`：

   ```yaml
   init_config_dns: true
   dns: [10.14.73.1]
   ```

   ⚠ 不要写在 hosts 的 `[组名:vars]` 里，它的优先级低于 env.yaml，会被覆盖。

优先级从高到低：机器行 > `group_vars/<组名>.yaml` > env.yaml > defaults.yaml。

- 只对 Ubuntu/Debian 生效（写 systemd-resolved）。
- `init_config_dns=false` 的机器上，init 以前写过的 `/etc/systemd/resolved.conf.d/99-init-dns.conf` 会被删掉，恢复成装机或 netplan 的配置。
- 只改 DNS 并验证：

  ```bash
  ansible-playbook playbook/init.yaml --tags dns
  ansible cluster -m shell -a 'resolvectl dns | grep -v "()"; ls /etc/systemd/resolved.conf.d/ 2>/dev/null'
  ```

  打开了的机器 `Global:` 是配的 DNS，目录里有 `99-init-dns.conf`；没打开的机器 DNS 是原来的，没有这个文件。

## 各组用途

| 组 | 用途 | 说明 |
|---|---|---|
| `[cluster]` | 全部机器 | `osinit_hostname_policy=inventory` 时，这里写的名字就是最终主机名 |
| `[init]` | 要跑 `init.yaml` 的机器 | 加新节点时只填新机器，不动已交付的老机器 |
| `[disk_lvm]` | 多盘组 LVM | 4 块同容量走 `mount-disk-lvm-containerfs.yaml`；2 或 4 块走 `mount-disk-lvm.yaml`。按盘的形态分组，不按有没有 GPU。旧组名 `[nvme_lvm]` 仍兼容 |
| `[disk_direct]` | 每块盘直接格式化挂载 | `mount-disk.yaml`；不限 NVMe（sd 盘也行），多块数据盘用机器行的 `data_disks`。旧组名 `[nvme_single]` 仍兼容 |
| `[containerd]` | 用 containerd 的节点 | k8s 节点都在这里 |
| `[docker]` | 装 docker 的节点 | docker 只给 Harbor 用。`accelerator_type=nvidia` 时装 nvidia-container-toolkit；docker 侧只支持 nvidia，dcu/npu 只在 containerd 生效 |
| `[harbor]` | Harbor 节点 | 1 台为单节点，2 台为双主（互相复制，不用 VIP，故障时手动切换）。往已有数据的 Harbor 加第二台时，有数据的那台写第一个 |
| `[cri_docker_nodes]` | cri-dockerd | 特殊场景才用，一般留空 |
| `[k8slb]` | haproxy + keepalived | 多 master 才需要，常和 master 共机；VIP 网卡按 `ansible_host` 自动探测 |
| `[k8s_master]` | 控制平面 | 建议奇数台；多 master 要配 `lbvip` 并部署 LB |
| `[k8s_node]` | worker | |
| `[etcd]` | 外置 etcd | 建议 3 或 5 台，可和 master 共机 |
| `[gpu]` | 有 GPU 的节点 | 打"有 GPU"标签 |
| `[gpu_driver]` | 装驱动 / 升内核 | 模板里默认注释掉。已交付的 GPU 节点只跑 os-init，不要放进这个组 |
| `[chronyserver]` | 内网 NTP server | 留空时全集群直接同步 `chrony_ip`；填 1 台它对内服务；填 2 台以上为主备。正在对内服务的机器不在本组时，init 会拦住，确认要撤掉加 `-e chrony_allow_demote=true` |
| `[ceph]` | Ceph 节点 | `host-ceph-set.yaml` 用它；`ceph-storage-net.yaml` 跑的是 `[cluster]`，限定范围用 `--limit ceph` |

## 扩缩容临时组（平时留空）

- **加 master / worker**：直接写进 `[k8s_master]` / `[k8s_node]`，跑时加 `--limit`，不需要 `master_to_add`。
- **`[node_to_delete]`**：删 k8s 节点，配合 `k8s-del-node.yaml`。
- **`[etcd_to_add]` / `[etcd_to_delete]`**：etcd 扩缩容。
- **`[master_to_delete]`**：只作用于 LB 层（haproxy / keepalived），和删 k8s master 无关，名字是历史遗留。`lb-haproxy-scale-remove.yaml` 用它找要卸载 LB 的机器。

> ⚠ 缩容 LB 前确认 `[master_to_delete]` 这个组在 hosts 里有声明。没声明时卸载那一步会静默跳过，playbook 仍然显示成功，被删节点上的服务其实还在跑。

## `[cluster:vars]` / `[all:vars]`

- `osinit_hostname_policy=inventory`：主机名以清单里写的名字为准。别改成 `ip`，会把 `cpu-001` 改成 `CPU-111` 这类名字。其它取值：`keep`、`explicit`。
- `ansible_python_interpreter`、`ansible_ssh_common_args`：保持模板里的值即可。
