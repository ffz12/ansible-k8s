# 集群插件

集群装好之后再装的组件，每类一个 role 加一个入口 playbook。目前实现了 device plugin。

## 约定

新增插件照这几条来，不用每次重新设计：

1. **同一类功能放一个 role，用 task 文件区分实现**。device plugin 就是一类：nvidia、rdma、以后的 dcu / npu 都是向 kubelet 上报扩展资源，所以都在 `roles/device-plugin/` 里，一个实现一个 `tasks/<名字>.yaml` + `templates/<名字>.yaml.j2`，`tasks/main.yaml` 只负责按变量 include。参照 `roles/cni`（calico / flannel / cilium 也是这么分的）。
2. **不是同一类的别往里塞**，各自一个 role 加入口 playbook，参照 `roles/nodelocaldns`。比如 dcgm-exporter 是导出 GPU 指标给 Prometheus 抓的，不上报资源，不装也不影响调度，所以不属于 device plugin。
3. **装哪些由 inventory 推导**，不手填。device plugin 读机器行上的 `accelerator_type`；不属于加速卡的能力（如 RDMA 网卡）单独给开关。
4. **离线 tar 放 `offline/artifacts/<role 名>/images/`，不进 git**，由 `scripts/offline/download-<role 名>-offline.sh` 生成，换机器 rsync 拷。
5. **镜像地址用 `{{ registry }}`**，不写死 Harbor 域名和项目名。推送复用 `docker load` 解析源名再 retag 的写法（tar 可能是 docker save 也可能是 containerd save，镜像名不一定是上游原名）。
6. **nodeSelector 用现成的节点标签**（`nvidia=true` 这类，由 `k8s-node-labels.yaml` 按 `accelerator_type` 打），不另造标签。
7. **manifest 落盘到 `/etc/kubernetes/`，apply 后等 DaemonSet ready**，并把实际 Pod 数与资源上报情况打出来 —— 没有匹配节点时 DaemonSet 期望副本是 0，`rollout status` 也会"成功"。

## device plugin

向 kubelet 上报扩展资源，Pod 才能在 `resources` 里申请。不装的话 GPU / RDMA 任务调度不上去。

```bash
ansible-playbook playbook/device-plugin.yaml                          # 按 accelerator_type 自动判断
                                                                      # 在线/离线由 env.yaml 的 is_offline 决定
ansible-playbook playbook/device-plugin.yaml -e device_plugins=nvidia  # 只装指定的
ansible-playbook playbook/device-plugin.yaml --check --diff            # 预览渲染结果, 不 apply
```

| 实现 | 上报的资源 | 装的条件 |
|---|---|---|
| nvidia | `nvidia.com/gpu` | 有 `accelerator_type=nvidia` 的节点时自动装 |
| rdma | `rdma/hca_shared_devices` | 默认装（`device_plugin_rdma: true`）。只落到带 `rdma=true` 标签的节点，该标签由 inventory 机器行的 `has_rdma=true` 打 —— 没写的机器不会跑这个 Pod。整个集群都没有 RDMA 网卡时在 env.yaml 设 `device_plugin_rdma: false` |

### 常用变量

全部变量见 `roles/device-plugin/defaults/main.yaml`，要改的写进 env.yaml。

| 变量 | 默认 | 说明 |
|---|---|---|
| `device_plugin_rdma` | `true` | 是否装 rdma 插件。没有 Mellanox 网卡的站点置 false |
| `nvidia_device_plugin_version` | `v0.17.1` | |
| `rdma_device_ids` | `["101b", "a2dc"]` | **各站点网卡型号不同，必须核对**，见下面 |
| `rdma_device_plugin_node_label` | `rdma` | 选节点用的标签，由机器行 `has_rdma=true` 打 |
| `rdma_hca_max` | `1000` | 一块 HCA 最多给多少个 Pod 用（shared 模式，不是独占） |
| `rdma_resource_name` | `hca_shared_devices` | 上报的资源名，Pod 里写 `rdma/hca_shared_devices` |

`rdma_device_ids` 填错的症状是：DaemonSet 正常起来，但节点上 `rdma/hca_shared_devices` 容量是 0 或者查不到。在 GPU 节点上查实际型号：

```bash
lspci -nn | grep -i mellanox        # 取 [15b3:xxxx] 里的 xxxx
```

一份 ConfigMap 由整个 DaemonSet 共用，插件在每台节点上拿 `vendors` + `deviceIDs` 去匹配本机实际存在的网卡：列表里有、本机没有的型号直接忽略。**所以混插不同型号时，把集群里在用的型号都列进去即可**，不用按节点分别配置。

常见型号（以 `lspci -nn` 实际输出为准）：`1017` CX-5、`101b` CX-6、`101d` CX-6 Dx、`1021` CX-7、`a2dc` BlueField-3。

### 离线镜像

```bash
# 联网机上拉, 默认双架构, 存进 offline/artifacts/device-plugin/images/<架构>/(不进 git)
bash scripts/offline/download-device-plugin-offline.sh
ARCH=amd64 bash scripts/offline/download-device-plugin-offline.sh   # 只要单架构
# 换机器: rsync -a offline/ root@控制机:~/ansible-k8s/offline/
```

两个上游镜像都是 amd64 + arm64 双架构。tar 按架构放子目录、文件名固定：

```
offline/artifacts/device-plugin/images/
├── amd64/{k8s-device-plugin.tar.gz, k8s-rdma-shared-dev-plugin.tar.gz}
└── arm64/{...}
```

role 自己探测有哪些架构（单架构站点只下一个也能跑），推 Harbor 时建 multi-arch manifest，kubelet 按节点架构自动取对应那层。手工放 tar 也行，放进对应架构的子目录即可。

**nvidia 按架构各渲一个 DaemonSet**：`libnvidia-ml.so.1` 的宿主机路径各架构不同（x86 在 `/lib/x86_64-linux-gnu/`，arm64 在 `/lib/aarch64-linux-gnu/`），而一个 DaemonSet 的 hostPath 没法按节点变，所以用 `kubernetes.io/arch` 的 nodeAffinity 分开。单架构集群只渲一个，名字不带后缀，和之前一致。rdma 不受影响（不挂宿主机库，一个 DaemonSet 覆盖所有架构）。

在线模式没有离线物料可探测，按 `device_plugin_online_archs`（默认 `[amd64]`）渲染，arm64 集群在 env.yaml 改成 `[amd64, arm64]` 或 `[arm64]`。

### 验收

```bash
# GPU 资源上报(装了插件的节点应有非空的 nvidia.com/gpu)
kubectl get nodes -l nvidia=true -o custom-columns='NODE:.metadata.name,GPU:.status.capacity.nvidia\.com/gpu'
# RDMA 资源上报
kubectl get nodes -l rdma=true -o custom-columns='NODE:.metadata.name,RDMA:.status.capacity.rdma/hca_shared_devices'
# Pod 是否都起来了
kubectl -n kube-system get ds nvidia-device-plugin-daemonset rdma-shared-dp-ds -o wide
```

跑完 playbook 会自动把上面前两项打出来。资源是 0 或空的话按这个顺序查：

1. 节点有没有对应标签（`kubectl get nodes -L nvidia -L rdma`）。没有就是 inventory 里漏写 `accelerator_type=nvidia` 或 `has_rdma=true`，补上后跑 `playbook/k8s-node-labels.yaml`。
2. 节点上 `nvidia-smi` 正常吗。驱动没装好的话插件起来也报不出资源。
3. 看插件 Pod 日志：`kubectl -n kube-system logs ds/nvidia-device-plugin-daemonset`。
4. rdma 还要核对 `rdma_device_ids` 与 `lspci -nn` 的结果。

## monitor

导出指标给 Prometheus 抓，不装不影响集群运行。目前只有 dcgm-exporter。

```bash
ansible-playbook playbook/monitor.yaml                 # 装 monitor_default_list(默认只有 dcgm-exporter)
ansible-playbook playbook/monitor.yaml --check --diff   # 预览
```

### dcgm-exporter

在 N 卡节点上导出 `DCGM_FI_DEV_*` 指标（GPU 利用率、显存、温度、功耗、时钟、NVLink）。用 `nvidia=true` 选节点，不用通用的 `gpu=true` —— dcgm 是 NVIDIA 专用，dcu / npu 节点跑它没意义。

| 变量 | 默认 | 说明 |
|---|---|---|
| `dcgm_exporter_version` | `4.5.2-4.8.1-ubuntu22.04` | tag 格式是 `<DCGM版本>-<exporter版本>-<系统>` |
| `monitor_scrape_mode` | `auto` | `auto` 探测有没有 ServiceMonitor CRD；也可写死 `servicemonitor` / `annotation` |
| `monitor_servicemonitor_labels` | `{}` | operator 的 `serviceMonitorSelector` 有标签要求时补上（kube-prometheus-stack 默认选 `release=<helm release 名>`） |
| `monitor_scrape_interval` | `30s` | |

**抓取方式**是这里唯一容易踩的地方。dcgm-exporter 只暴露 `:9400/metrics`，要靠 Prometheus 来抓，而怎么被发现取决于 Prometheus 的形态：

| 集群情况 | 生成什么 | 要注意 |
|---|---|---|
| 有 `servicemonitors.monitoring.coreos.com` CRD（prometheus-operator） | DaemonSet + Service + ServiceMonitor | operator 的 `serviceMonitorSelector` 若有标签要求，没配 `monitor_servicemonitor_labels` 就不会被选中 |
| 没有该 CRD（裸 Prometheus） | DaemonSet + Service + Pod 注解 | 要求 Prometheus 的 `scrape_configs` 开了 kubernetes_sd 的 pod 发现 |

判错或没配对的症状是**静默**的：Pod 正常跑、`curl :9400/metrics` 有数据，但 Prometheus 里查不到指标、Grafana 图全空。playbook 会把探测到的方式和对应的确认命令打出来。

### 离线镜像与 dashboard

```bash
bash scripts/offline/download-monitor-offline.sh      # 默认双架构, ARCH=amd64 只拉一个
```

存进 `offline/artifacts/monitor/images/<架构>/dcgm-exporter.tar.gz`（不进 git）。上游镜像是 amd64 + arm64 双架构。

配套 dashboard 在 `playbook/roles/monitor/files/dashboards/gpu-node.json`（标题「GPU Nodes v2」），**需手工导入** Grafana，数据源选 `prometheus`。没做成自动导入是因为各站点 Grafana 的装法和认证方式不一样。

### 验收

```bash
kubectl -n kube-system get ds dcgm-exporter -o wide
# exporter 自己有没有数据
pod=$(kubectl -n kube-system get pod -l app=dcgm-exporter -o name | head -1)
kubectl -n kube-system exec $pod -- curl -s localhost:9400/metrics | grep -c '^DCGM_FI_DEV_'
# Prometheus 有没有抓到: 页面 Status -> Targets 里找 dcgm-exporter
```

前两条 playbook 跑完会自动打印。第三条必须自己看 —— 前两条通过只代表 exporter 正常，不代表 Prometheus 抓到了。

### 加一种新的加速卡

以 dcu 为例：

1. 写 `roles/device-plugin/tasks/dcu.yaml`，照 `nvidia.yaml` 的结构（推镜像 → 渲染 → apply → 等 ready → 打印资源上报）。
2. 写 `roles/device-plugin/templates/dcu-device-plugin.yml.j2`，nodeSelector 用 `dcu=true`。
3. `defaults/main.yaml` 里加版本、tar 名、镜像、节点标签几个变量。
4. `tasks/main.yaml` 的 assert 里把 `dcu` 加进已支持列表。
5. 下载脚本里加一行 `pull`。

inventory 里有 `accelerator_type=dcu` 的节点时就会自动装，不用改入口 playbook。
