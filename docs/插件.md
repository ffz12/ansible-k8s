# 集群插件

集群装好之后再装的组件，每类一个 role 加一个入口 playbook。目前实现了 device plugin。

## 约定

新增插件照这几条来，不用每次重新设计：

1. **同一类功能放一个 role，用 task 文件区分实现**。device plugin 就是一类：nvidia、rdma、以后的 dcu / npu 都是向 kubelet 上报扩展资源，所以都在 `roles/device-plugin/` 里，一个实现一个 `tasks/<名字>.yaml` + `templates/<名字>.yaml.j2`，`tasks/main.yaml` 只负责按变量 include。参照 `roles/cni`（calico / flannel / cilium 也是这么分的）。
2. **不是同一类的别往里塞**，各自一个 role 加入口 playbook，参照 `roles/nodelocaldns`。比如 dcgm-exporter 是导出 GPU 指标给 Prometheus 抓的，不上报资源，不装也不影响调度，所以不属于 device plugin。
3. **装哪些由 inventory 推导**，不手填。device plugin 读机器行上的 `accelerator_type`；不属于加速卡的能力（如 RDMA 网卡）单独给开关。
4. **离线 tar 放 `offline/artifacts/<role 名>/images/`，不进 git**，由 `scripts/offline/download-<role 名>-offline.sh` 生成，换机器 rsync 拷。
5. **镜像地址用 `{{ registry }}`**，不写死 Harbor 域名和项目名。推送复用 `docker load` 解析源名再 retag 的写法（tar 可能是 docker save 也可能是 containerd save，镜像名不一定是上游原名）。
6. **nodeSelector 用现成的节点标签**（`nvidia=true` 这类，由 `k8s-node-labels.yaml` 按 `accelerator_type` 打），不另造标签。
7. **manifest 落盘到 `/etc/kubernetes/`，apply 后等 DaemonSet ready**，并把实际 Pod 数与资源上报情况打出来 —— 没有匹配节点时 DaemonSet 期望副本是 0，`rollout status` 也会"成功"。

## device plugin

向 kubelet 上报扩展资源，Pod 才能在 `resources` 里申请。不装的话 GPU / RDMA 任务调度不上去。

```bash
ansible-playbook playbook/device-plugin.yaml                          # 按 accelerator_type 自动判断
ansible-playbook playbook/device-plugin.yaml -e is_offline=true        # 离线(先备好 tar)
ansible-playbook playbook/device-plugin.yaml -e device_plugins=nvidia  # 只装指定的
ansible-playbook playbook/device-plugin.yaml --check --diff            # 预览渲染结果, 不 apply
```

| 实现 | 上报的资源 | 装的条件 |
|---|---|---|
| nvidia | `nvidia.com/gpu` | 有 `accelerator_type=nvidia` 的节点时自动装 |
| rdma | `rdma/hca_shared_devices` | 默认装（RDMA 是网卡能力，不在 `accelerator_type` 里，所以单独一个开关）。没有 RDMA 网卡的站点在 env.yaml 设 `device_plugin_rdma: false` |

### 常用变量

全部变量见 `roles/device-plugin/defaults/main.yaml`，要改的写进 env.yaml。

| 变量 | 默认 | 说明 |
|---|---|---|
| `device_plugin_rdma` | `true` | 是否装 rdma 插件。没有 Mellanox 网卡的站点置 false |
| `nvidia_device_plugin_version` | `v0.17.1` | |
| `nvidia_device_plugin_privileged` | `true` | 现网取值。装了 nvidia-container-toolkit 通常不需要特权，确认不需要可置 false |
| `nvidia_device_plugin_mount_libnvidia_ml` | `true` | 现网取值。容器内找不到 libnvidia-ml 时才需要 |
| `rdma_device_ids` | `["101b", "a2dc"]` | **各站点网卡型号不同，必须核对**，见下面 |
| `rdma_hca_max` | `1000` | 一块 HCA 最多给多少个 Pod 用（shared 模式，不是独占） |
| `rdma_resource_name` | `hca_shared_devices` | 上报的资源名，Pod 里写 `rdma/hca_shared_devices` |

`rdma_device_ids` 填错的症状是：DaemonSet 正常起来，但节点上 `rdma/hca_shared_devices` 容量是 0 或者查不到。在 GPU 节点上查实际型号：

```bash
lspci -nn | grep -i mellanox        # 取 [15b3:xxxx] 里的 xxxx
```

### 离线镜像

```bash
# 联网机上拉, 存进 offline/artifacts/device-plugin/images/(不进 git)
bash scripts/offline/download-device-plugin-offline.sh
# 换机器: rsync -a offline/ root@控制机:~/ansible-k8s/offline/
```

tar 文件名固定（`k8s-device-plugin.tar.gz`、`k8s-rdma-shared-dev-plugin.tar.gz`），role 按名字找。手工放也行，放进上面那个目录即可。

### 验收

```bash
# GPU 资源上报(装了插件的节点应有非空的 nvidia.com/gpu)
kubectl get nodes -l nvidia=true -o custom-columns='NODE:.metadata.name,GPU:.status.capacity.nvidia\.com/gpu'
# RDMA 资源上报
kubectl get nodes -l nvidia=true -o custom-columns='NODE:.metadata.name,RDMA:.status.capacity.rdma/hca_shared_devices'
# Pod 是否都起来了
kubectl -n kube-system get ds nvidia-device-plugin-daemonset rdma-shared-dp-ds -o wide
```

跑完 playbook 会自动把上面前两项打出来。资源是 0 或空的话按这个顺序查：

1. 节点有没有 `nvidia=true` 标签（`kubectl get nodes -L nvidia`）。没有就是 inventory 里漏写 `accelerator_type=nvidia`，补上后跑 `playbook/k8s-node-labels.yaml`。
2. 节点上 `nvidia-smi` 正常吗。驱动没装好的话插件起来也报不出资源。
3. 看插件 Pod 日志：`kubectl -n kube-system logs ds/nvidia-device-plugin-daemonset`。
4. rdma 还要核对 `rdma_device_ids` 与 `lspci -nn` 的结果。

### 加一种新的加速卡

以 dcu 为例：

1. 写 `roles/device-plugin/tasks/dcu.yaml`，照 `nvidia.yaml` 的结构（推镜像 → 渲染 → apply → 等 ready → 打印资源上报）。
2. 写 `roles/device-plugin/templates/dcu-device-plugin.yml.j2`，nodeSelector 用 `dcu=true`。
3. `defaults/main.yaml` 里加版本、tar 名、镜像、节点标签几个变量。
4. `tasks/main.yaml` 的 assert 里把 `dcu` 加进已支持列表。
5. 下载脚本里加一行 `pull`。

inventory 里有 `accelerator_type=dcu` 的节点时就会自动装，不用改入口 playbook。
